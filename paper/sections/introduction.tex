Computer vision models have moved rapidly from research prototypes into production pipelines
and edge deployments, powering applications from autonomous inspection robots to real-time
video analytics at the network edge.

\paragraph{Problem.}
General-purpose model-serving systems such as NVIDIA Triton Inference Server~\cite{nvidia2023triton}
and TorchServe~\cite{pytorch2023torchserve} are architected for cloud data centers. They
require Kubernetes or Docker orchestration, expose complex gRPC configuration surfaces, and
carry Python or JVM runtimes that can exceed several gigabytes of disk and memory overhead.
At the other extreme, deploying a model by running a bare PyTorch script provides neither
a stable REST API, nor lifecycle management (loading, unloading, VRAM accounting), nor the
ability to serve multiple models through a single endpoint.
A second, less-discussed problem is licensing. The most widely used detection models, the YOLO
series, are released under the GNU Affero General Public License v3.0
(AGPL-3.0)~\cite{ultralytics2023yolo,agpllicense}, which requires any software that incorporates
or exposes YOLO as a network service to publish its entire source code under AGPL-3.0. That
rules out closed-source or commercial use without a paid commercial license.

\paragraph{Gap.}
No existing solution simultaneously provides
(a)~a complete CV serving stack (detection, segmentation, open-vocabulary
detection, classification, depth estimation, embedding, and grasp synthesis) in a single
deployable unit;
(b)~a load-time policy that refuses to load any model whose declared license is
outside a permissive allowlist (Apache-2.0, MIT, or BSD), so that downstream products can use it
without license encumbrance; and
(c)~a single self-contained binary that runs on edge hardware without a Python
interpreter, a GPU driver stack beyond what ONNX Runtime needs, or a container runtime.

\paragraph{VisionServe.}
We present VisionServe, a lightweight inference server written in Go and designed to be
the ``Ollama for Computer Vision''~\cite{ollama2023}: one binary, pulled from a local model
registry, serving any of 19 registered models over a REST API with no Python dependency.
All inference is delegated to ONNX Runtime~\cite{onnxruntime} via a thin cgo binding,
which enables automatic fallback across execution providers (TensorRT, CUDA, CoreML,
DirectML, OpenVINO, CPU) without changes to model code.
The defining feature is that a license policy is enforced inside the runtime at load time: the
model registry parser validates each model's declared license against an Apache-2.0/MIT/BSD
allowlist at startup and refuses to load any model that fails. In an opt-in verified mode the
gate is hardened further, binding the declared license to the weight bytes (sha256), to an
audited \texttt{source\_url}, and to a maintainer-audited license-provenance ledger, so a
manifest relabeled by a contributor is refused by a record the contributor does not control
(Section~\ref{sec:catalog}).

\paragraph{Contributions.}
The primary contribution is the license gate; the remaining items are the system and the
measurements that support it.

\begin{itemize}
  \item \textbf{A load-time license-policy gate (primary contribution).} To our knowledge this
        is the first inference runtime to enforce a permissive-license allowlist
        (Apache-2.0/MIT/BSD) at model-load time. In verified mode it binds the declared license
        to specific weight bytes (sha256), an audited \texttt{source\_url}, and a
        maintainer-audited license-provenance ledger that cross-checks the declared license
        against an independent human audit of the upstream, entirely offline in one binary. We
        position the gate against build-time SCA scanners, deploy-time admission controllers, and
        model signing, none of which enforces a license policy at load time, and give a threat
        model exercised by a reproducible adversarial demonstration: an AGPL-declared model, a
        weight-hash mismatch, an unaudited source, and a manifest whose permissive-but-wrong
        license diverges from the audited ledger are each refused. The ledger secures the curated
        catalog by separating contributor and maintainer authority; it is not a universal license
        oracle for arbitrary uploads.

  \item \textbf{A complete, Python-free CV serving system around the gate.} VisionServe serves 19
        registered models across seven task types behind one unified \texttt{Result} schema and a
        single binary. The single-binary, Python-free, and multi-EP properties are shared with
        prior systems (llama.cpp, ONNX Runtime); our contribution on these axes is to bring them
        together under the license gate for multi-task computer vision.

  \item \textbf{A measured serving-overhead characterization (supporting evidence).} On identical
        ONNX, the single Go binary matches an eight-process FastAPI+ONNX-Runtime deployment in
        peak goodput at a fraction of the memory, and reaches roughly $8\times$ the goodput of the
        single-worker default that most teams ship (585 vs.\ 652~rps at eight workers; the
        advantage narrows for compute-heavy models). A latency decomposition attributes the
        per-request cost to pure-Go JPEG decode, not the GPU (ORT~Run $<$1\,ms), and with a
        pre-decoded tensor VisionServe matches a default-configuration Triton's serving ceiling.
        This is the CV-specific instance of non-inference overhead dominating small-DNN
        serving~\cite{abouelhamayed2024beyond}. Results cover an RTX~A6000 and a Jetson AGX Orin,
        with export and serving preserving ImageNet Top-1 to within 0.5\% (16 of 19 models
        benchmarked).
\end{itemize}
